What is Neote?

Neote is a small transpiler that turns a single .neote file into a complete, runnable web page — HTML for structure, JavaScript for behavior, both generated from the same source. You write one file; the IDE compiles it, runs it inside a sandboxed preview, and streams console output straight back to your terminal.

The trick is that every line in a Neote file is exactly one of three kinds. The transpiler looks at the first character of each line and routes it accordingly:

Starts withKindWhat happens
$DOM loaderDeclaratively emits an HTML element — $hd("Hi") becomes <header>Hi</header>.
<Raw HTMLPassed through verbatim — handy for <style> blocks or markup Neote has no loader for.
anything elseJS logicCompiled as JavaScript, with Neote keyword shortcuts (st→let, showcase→console.log…) swapped in.

That's the whole mental model. Mix those three line kinds freely — a header, a button, an event handler, a styled section — and you have a working app in one file. Hit Run on the example below to see it compile and execute live:

welcome.neote
// Welcome to Neote! Press Run.
$hd("Welcome to Neote IDE ⚡") /id="mainHeader"
$p("Neote blends declarative $ DOM loaders with clean keyword shortcuts.")
$div("Try clicking the button below!") /class="intro-box"

$input("Enter your developer alias...") /id="aliasInput"
$btn("Say Hello") /id="greetBtn" /class="primary-btn"
$ft("Built with Neote Transpiler • Black & Purple Edition")

st appName = "Neote IDE"
st version = 1.0
showcase("Booting " + appName + " v" + version + "...")

st btn = doc.element("greetBtn")
st input = doc.element("aliasInput")

btn.sense("click", func() {
  st user = input.value.trim() || "Creator"
  showcase("Greeting triggered for user: " + user)
  notify("Welcome aboard, " + user + "!")
})

Anatomy of a File
02
Start Here · How it compiles

Anatomy of a .neote File

A Neote file is plain text — no boilerplate, no <!DOCTYPE>, no closing tags to balance. The transpiler reads it top to bottom, splits it into lines, and emits two parallel streams: an HTML body (everything that came from $ and < lines) and a JavaScript block (everything from logic lines, with keywords translated). The two are combined into one sandboxed document and executed.

The four ingredients

  • Comments — any // to end of line is ignored, just like JavaScript. Use them to annotate sections.
  • DOM loaders — $hd("Title"), $btn("Go") /id="go", etc. These build your visible page.
  • Raw HTML — lines beginning with < pass straight through. Ideal for <style> blocks.
  • Logic — everything else is JavaScript, written with Neote's keyword shortcuts (st, func, ret, for…).

Here is a tiny but complete file that uses all four. Run it, then click { } Transpiled to see exactly what the compiler produced:

anatomy.neote
// 1. A comment — ignored by the compiler.

// 2. DOM loaders build the page:
$hd("Counter Demo")
$p("Click the button to count up.")
$btn("Click me") /id="counter"
$p("0") /id="display"

// 3. Raw HTML for a custom style:
<style>#display { font-size: 2rem; color: #c084fc; font-weight: 800; }</style>

// 4. Logic, with keyword shortcuts:
st count = 0
st btn = doc.element("counter")
st display = doc.element("display")

btn.sense("click", func() {
  count = count + 1
  display.innerText = count
  showcase("Count is now " + count)
})
Live Preview ready clear
💡 Line numbers stay aligned

The transpiler intentionally keeps blank lines and $-loader lines as empty entries in the JavaScript stream. That way, if your logic throws a runtime error on line 12, the line number reported in the terminal matches the line you see in the editor — no mental offset required.

Files, folders, and persistence

In the Neote IDE, your files live in a virtual tree called neote_tree, backed by localStorage. Create .neote, .md, and .txt files inside nested folders, drag to reorganize, and the whole workspace survives a page refresh. Markdown and plain-text files render in their own viewers; only .neote files transpile and run.

✓ Two ways to see the result

The toolbar's Run button (or Ctrl+Enter) renders the compiled app into the preview pane. The Transpile button shows the generated HTML/JS instead — perfect when you want to confirm what a loader expanded to, or debug a translation. On this course, the { } Transpiled button does the same thing inline.

$ DOM Loaders
03
The Language · Structure

$ DOM Loaders

A DOM loader is the declarative heart of Neote. Every line that starts with $ calls a named loader, hands it arguments in parentheses, and optionally appends slash-prefixed attributes. The compiler turns that one line into exactly one HTML element.

The grammar is fixed and tiny:

syntax.neote
$loader("argument", "argument", ...) /attr="value" /attr="value"

What the first argument means depends on the loader's attribute mode. There are seven modes, and they decide whether the argument becomes inner text, a placeholder, a URL, and so on. Knowing the mode for each loader is the key to using them fluently.

The seven attribute modes

textInner text of the element$p("Hi")<p>Hi</p>
placeholderThe placeholder attribute$input("Search...")<input placeholder="Search..." />
srcThe src attribute$img("cat.png")<img src="cat.png" />
hrefarg #1 = href, arg #2 = link text$href("u","t")<a href="u">t</a>
actionThe action attribute$form("/submit")<form action="/submit"></form>
nameThe name attribute$select("country")<select name="country"></select>
noneNo argument taken$hr()<hr />

⚠ Unknown loaders fail loudly

If you mistype a loader — say $buton("Hi") — the transpiler raises a ReferenceError listing every valid loader. The error appears in the terminal and as a wavy red underline in the editor. There is no silent fallback.

Inline Attributes
04
The Language · Styling

Inline Attributes with /

Loaders generate the element; slash attributes dress it up. Anything written as /key="value" after a loader call becomes a literal attribute on the emitted tag. Chain as many as you need — order does not matter.

attributes.neote
$btn("Save") /id="saveBtn" /class="primary" /disabled="true"
// becomes: <button id="saveBtn" class="primary" disabled="true">Save</button>

The slash syntax is deliberate: it keeps the loader's parentheses focused on content while stashing metadata out of the way. You read $btn("Save") first, then glance at the trailing /id and /class if you care about wiring.

The attributes you'll reach for most

  • /id="…" — give the element an id so logic lines can grab it with doc.element("…").
  • /class="…" — attach one or more CSS classes (space-separated).
  • /style="…" — inline CSS, useful for quick one-offs.
  • /type="…" — input type: "text", "email", "password", "number", "checkbox".
  • /target="_blank" — open $href links in a new tab.
  • /value="…", /srcset="…", /controls, /autoplay — any real HTML attribute is valid here.
💡 Any HTML attribute works

The parser accepts any /name="value" pair where the name starts with a letter, colon, or underscore. You are not limited to a fixed list — if the underlying HTML tag supports it, you can attach it.

Combine attributes with a <style> block and you have a fully styled component, no external CSS file required:

styled-card.neote
<style>.card { background: linear-gradient(135deg, #7c3aed, #9333ea); color: #fff; padding: 20px 24px; border-radius: 14px; max-width: 340px; box-shadow: 0 10px 30px rgba(124,58,237,.4); margin: 8px 0; border: 0; } .card-btn { background: #fff; color: #7c3aed; }</style>

$hd("Neote Card") /class="card"
$p("Built from $hd and $p with /class, styled by a single-line <style> block.") /class="card"
$btn("Do something") /id="cardBtn" /class="card-btn"
$ft("•")
Live Preview ready clear
⚠ Quotes are required

Every attribute value must be wrapped in matching double or single quotes: /class="btn" or /class='btn'. A bare /class=btn is rejected with a Malformed inline attribute syntax error. The value may itself contain spaces (for multiple classes) — just keep it inside the quotes.

The Language · Logic

Keyword Shortcuts (the guide)

On logic lines, Neote swaps short mnemonic tokens for their verbose JavaScript equivalents using a dictionary named guide. Write st and the compiler emits let; write showcase and it emits console.log. The shortcuts are optional — plain JavaScript works too — but they make dense logic readable.

The golden rule: where keywords do and don't apply

The translator is line-aware and string-aware. It only touches words on logic lines — never inside string literals, never inside comments, and never on lines that start with $ or <. That means a literal "st" in a message stays "st", and a $p("st is short for let") keeps its text intact.

💡 The seven flow keywords are no-ops

if, else, for, while, async, var, and fetch translate to themselves. They are in guide for completeness and autocomplete, not because they change anything — but having them listed means the editor highlights them as Neote keywords.

This example exercises every category. Run it and watch the terminal fill with showcase output:

keywords.neote
$hd("Keyword Tour")
$p("Open the terminal below to see each keyword in action.")

// variables
st name = "Neote"
con version = 1.0
showcase("Loaded " + name + " v" + version)

// functions & control flow
func greet(who) {
  ret "Hello, " + who + "!"
}
showcase(greet("developer"))

for (st i = 1; i <= 3; i = i + 1) {
  showcase("loop tick " + i)
}

// timing
timeout(func() {
  showcase("...fired after 600ms")
}, 600)

// DOM helpers read back to us
$btn("ping") /id="pingBtn"
st btn = doc.element("pingBtn")
btn.sense("click", func() {
  warn("button was clicked")
})

// string-aware: "st" inside text is NOT translated
showcase("the token 'st' still appears as text")

✓ Mix freely with plain JavaScript

Nothing forces you to use shortcuts. const, document.getElementById, addEventListener, async/await all work untouched. Use the short forms where they help readability and the long forms where clarity matters more than brevity — often in shared or complex logic.

Raw HTML & Styles
06
The Language · Escape hatch

Raw HTML & Styles

When a line begins with <, the transpiler copies it into the HTML body verbatim — no parsing, no keyword substitution, no loader expansion. This is your escape hatch for the things Neote's loaders don't cover: <style> blocks, <script src> includes, complex nested markup, or a snippet you already have.

The most common use: styling

Neote has no $style loader, and that's intentional. Instead, drop a <style> block anywhere among your $ lines. The browser applies the CSS just as it would in any HTML document, and your loaders' /class attributes hook into it.

⚠ <style> blocks must be one line

The transpiler decides what a line is by looking at its first non-space character. Only lines that begin with < are passed through as raw HTML — every other line is compiled as JavaScript. So a multi-line <style> block breaks: the opening <style> and closing </style> pass through fine, but the CSS rule lines in between (body { ... }, .tile { ... }) are fed to the JavaScript compiler and throw syntax errors. Keep the entire <style>…</style> on a single line. Long CSS is fine — just let it wrap visually in the editor.

💡 Raw HTML lines may be indented

The “starts with <” test runs on the trimmed line, so indented raw HTML like   <div class="tile">1</div> still passes through. That means nested raw markup — a <div class="grid"> wrapping several <div class="tile"> children — works across multiple lines, as the example below shows. Only <style> and <script> content suffers the single-line constraint, because their bodies are not themselves tag lines.

styles.neote
<style>body { font-family: 'JetBrains Mono', monospace; } .grid { display: grid; grid-template-columns: repeat(3, 1fr); gap: 10px; max-width: 360px; } .tile { background: #1b172b; border: 1px solid #382f57; border-radius: 10px; padding: 18px; text-align: center; color: #c084fc; font-weight: 700; } .tile.hot { background: linear-gradient(135deg, #7c3aed, #d946ef); color: #fff; border-color: transparent; }</style>

$hd("CSS Grid via <style>")
<div class="grid">
  <div class="tile">1</div>
  <div class="tile hot">2</div>
  <div class="tile">3</div>
  <div class="tile">4</div>
  <div class="tile hot">5</div>
  <div class="tile">6</div>
</div>
$ft("Raw <div> nesting + a single-line <style> block.")
Live Preview ready clear
💡 When to choose raw over a loader

Reach for a $ loader when an element maps cleanly to one tag and you only need text plus a few attributes. Switch to a raw < line when you need deeply nested children, attributes the slash syntax can't express cleanly, or a non-element tag like <style>, <meta>, or <link>. Both land in the same output document.

⚠ Raw lines are not translated

Because < lines bypass the guide dictionary, writing st inside a raw HTML block leaves it as the literal text st. If you need logic, keep it on its own logic line — never embed JavaScript inside a raw block expecting shortcuts to apply.

Events & Interactivity
07
Building Blocks · Behavior

Events & Interactivity

A page is only useful when it responds. Neote wires behavior the same way the DOM does — pick the element, call sense() (which is addEventListener), and hand it an event name plus a function. The pattern is so common that almost every interactive Neote file follows the same three-step shape.

The three-step pattern

  1. Render the element with a /id so you can find it later: $btn("Go") /id="goBtn".
  2. Grab it in a logic line: st btn = doc.element("goBtn").
  3. Listen for the event: btn.sense("click", func() { ... }).

Inside the handler, read state from the page (an input's .value, a checkbox's .checked) and write results back (an element's .innerText, .style, or new children via doc.create() and append()).

events.neote
$hd("Echo Box")
$p("Type below, then press Echo.")
$input("Type something...") /id="echoInput" /type="text"
$btn("Echo") /id="echoBtn"
$btn("Clear") /id="clearBtn"
$p("") /id="echoOut"

st input = doc.element("echoInput")
st out   = doc.element("echoOut")
st echoBtn   = doc.element("echoBtn")
st clearBtn  = doc.element("clearBtn")

echoBtn.sense("click", func() {
  st msg = input.value.trim()
  if (msg === "") {
    warn("nothing to echo")
    out.innerText = "(empty)"
  } else {
    out.innerText = "→ " + msg
    showcase("echoed: " + msg)
  }
})

clearBtn.sense("click", func() {
  input.value = ""
  out.innerText = ""
  showcase("cleared")
})
Live Preview ready clear

Keyboard events and notify / qstn

The same sense() works for any event — "input", "change", "keydown", "submit". Combine it with the output keywords notify (alert) and qstn (prompt) for quick dialog-driven flows.

dialogs.neote
$hd("Ask & Tell")
$btn("What's your name?") /id="askBtn"
$p("Live keypress count: 0") /id="countLabel"
$input("type here...") /id="typeBox"

st askBtn = doc.element("askBtn")
askBtn.sense("click", func() {
  st reply = qstn("Enter your name:")
  if (reply) {
    notify("Nice to meet you, " + reply + "!")
    showcase("user answered: " + reply)
  } else {
    warn("user cancelled the prompt")
  }
})

st box = doc.element("typeBox")
st label = doc.element("countLabel")
st n = 0
box.sense("input", func() {
  n = n + 1
  label.innerText = "Live keypress count: " + n
})
Live Preview ready clear
✓ Prefer /id over traversal

doc.element("x") (which is document.getElementById) is the fastest, most readable way to reach an element. Use sel(".class") (querySelector) only when you genuinely need a CSS selector. Stable ids also keep your wiring obvious when a file grows past a screenful.

Forms & Inputs

Building Blocks · Input

Forms & Inputs

Neote covers the full form vocabulary: $form, $input, $textarea, $label, $select + $option. The /type attribute turns a plain input into a password, email, number, checkbox, or date field, exactly as in HTML.

Remember the modes: $input and $textarea take a placeholder; $select takes a name; $form takes an action; $label and $option take text. Add /id, /value, /name, and /for as needed.

signup.neote
<style>label { display: block; font-size: .85rem; color: #c084fc; font-weight: 600; margin: 8px 0 2px; }</style>

$hd("Sign Up")
$form("#") /id="signupForm"
$label("Email") /for="emailField"
$input("you@example.com") /id="emailField" /type="email" /name="email"
$label("Password") /for="pwField"
$input("••••••••") /id="pwField" /type="password" /name="pw"
$label("Plan") /for="planField"
$select("plan") /id="planField"
$option("Free")
$option("Pro")
$option("Team")
$label("Bio") /for="bioField"
$textarea("Tell us about yourself...") /id="bioField"
$btn("Create account") /id="submitBtn"
$p("") /id="formStatus"

st email = doc.element("emailField")
st pw = doc.element("pwField")
st plan = doc.element("planField")
st status = doc.element("formStatus")
st submitBtn = doc.element("submitBtn")

submitBtn.sense("click", func() {
  if (email.value === "" || pw.value === "") {
    status.innerText = "✗ email and password are required"
    error("missing fields")
  } else {
    st summary = email.value + " · " + plan.value + " · bio: " + (doc.element("bioField").value || "(none)")
    status.innerText = "✓ welcome, " + email.value
    showcase("submitted → " + summary)
  }
})
Live Preview ready clear
💡 Reading a select's value

A $select emits a real <select name="…"> tag. Read its current choice with sel.value — the browser returns the text of the selected <option>. Add /value="pro" on an $option if you want a value distinct from its visible text.

⚠ Wire the button's click, not the form's submit

Every $ loader emits a top-level element, so the field loaders above produce siblings, not children of the $form. That means the submit button is not inside the form, and a form.sense("submit", …) listener will never fire — nothing triggers it. The idiomatic fix is to listen for "click" on the button itself (submitBtn.sense("click", func() { … })) and read each field by its /id, exactly as the example does. If you genuinely need a real nested form, build it with raw < HTML instead.

Lists & Tables
09
Building Blocks · Data display

Lists & Tables

For repeating data, Neote gives you list loaders ($ul, $ol, $li) and table loaders ($table, $tr, $th, $td). They emit the matching HTML tags, so the browser's default list and table styling applies — and your <style> blocks can refine it.

The cleanest way to build a list from data is to write the static loaders first, then push extra items from logic using doc.create() and append(). That keeps the declarative shell readable while still letting data drive the result.

list-builder.neote
$hd("Task Queue")
$p("Static head items + items appended from data:")
$ol("") /id="tasks"
$btn("Add random task") /id="addBtn"

st list = doc.element("tasks")
st tasks = ["ship the build", "review the PR", "write docs"]

// render the initial array
for (st i = 0; i < tasks.length; i = i + 1) {
  st li = doc.create("li")
  li.innerText = tasks[i]
  list.append(li)
}

st btn = doc.element("addBtn")
st pool = ["fix lint", "merge main", "deploy staging", "open a ticket", "reply to review"]
btn.sense("click", func() {
  st pick = pool[Math.floor(Math.random() * pool.length)]
  st li = doc.create("li")
  li.innerText = pick + "  (added)"
  list.append(li)
  showcase("added task: " + pick)
})

✓ Empty-text containers are your hooks

The loader still emits the tag (so children can be appended or rows stacked), and the /id gives logic a stable handle. Use this idiom whenever a container's job is to hold children rather than display its own text.

Media & Embeds

The src-mode loaders — $img, $video, $audio, and $loader (which emits an <iframe>) — drop rich media onto the page in a single line. The first argument is always the source URL; everything else is a slash attribute.

Images and video

media.neote
$hd("Media Sampler")

$p("Image with a class:")
$img("https://picsum.photos/seed/neote-media/360/160") /class="framed"

$p("Video with controls and autoplay muted:")
$video("https://interactive-examples.mdn.mozilla.net/media/cc0-videos/flower.mp4") /controls="true" /autoplay="true" /muted="true" /class="framed"

<style>.framed { border-radius: 12px; border: 1px solid #2e2747; max-width: 100%; }</style>

$ft("All src-mode loaders take the URL as their first argument.")

⚠ Boolean attributes take a value

The slash-attribute grammar requires /key="value". For boolean HTML attributes like controls, autoplay, muted, loop, write them as /controls="true" or /muted="" — the parser needs the equals-and-quotes form. A bare /controls is rejected as malformed.

Embedding other pages with $loader

$loader("url") emits an <iframe> — handy for embedding a YouTube video, a CodePen, a map, or another Neote file's transpiled output. Note: in the course playground the iframe is itself sandboxed, so some embeds that require allow-same-origin may refuse to render; the IDE's preview pane has broader permissions.

embed.neote
$hd("Embedded View")
$p("$loader emits an <iframe> pointing at any URL.")
$loader("https://example.com") /class="framed"

<style>iframe.framed { min-height: 200px; border-radius: 12px; border: 1px solid #2e2747; }</style>

$ft("Use $loader for maps, video players, or composing Neote outputs.")

Canvas for graphics

$canvas("") emits a <canvas> tag. Add /width and /height, then draw from logic by fetching the 2D context. This is the bridge into imperative drawing while keeping the element itself declarative.

canvas.neote
$hd("Canvas Gradient")
$canvas("") /id="cv" /width="320" /height="180" /style="border-radius:12px"

st cv = doc.element("cv")
st ctx = cv.getContext("2d")
st grad = ctx.createLinearGradient(0, 0, 320, 180)
grad.addColorStop(0, "#7c3aed")
grad.addColorStop(1, "#d946ef")
ctx.fillStyle = grad
ctx.fillRect(0, 0, 320, 180)

Async & Fetch

Logic lines compile to real JavaScript, so the full async toolkit is available: async functions, wait (that's await), fetch, json (JSON.parse), and stringify (JSON.stringify). Build a UI shell with loaders, then drive it from a network request.

💡 The pattern

Declare func async load() { ... }, call wait fetch(url), parse with wait res.text() or json(...)`, and write the result into an element. Wrap the call in a try / catch to handle failures gracefully. The async keywords translate cleanly because they live on logic lines, not inside strings.

fetcher.neote
$hd("Random Joke")
$p("Click to fetch from a public API:")
$btn("Get joke") /id="jokeBtn"
$p("loading...") /id="jokeOut"
$ft("Powered by jokeapi.jvns.ca")

st btn = doc.element("jokeBtn")
st out = doc.element("jokeOut")

async func loadJoke() {
  out.innerText = "fetching..."
  try {
    st res = wait fetch("https://v2.jokeapi.dev/joke/Any?type=single")
    st data = json(wait res.text())
    if (data.joke) {
      out.innerText = data.joke
      showcase("got joke (" + data.joke.length + " chars)")
    } else {
      out.innerText = "(no joke field)"
      warn("unexpected shape: " + stringify(data).slice(0, 80))
    }
  } catch (e) {
    out.innerText = "✗ request failed"
    error(String(e))
  }
}

btn.sense("click", loadJoke)

The Terminal CLI

Below the editor in the Neote IDE sits a terminal with four tabs — Main (runtime logs), Errors, Info (file metadata), and Help. It also has a command line. Type a command and press enter; the IDE executes it against your workspace.

Command reference

CommandWhat it does
code.run()Execute the active file (same as the Run button or Ctrl+Enter).
code.clear()Clear the editor's current contents.
code.refresh()Reload the preview pane without re-running.
code.stop()Halt execution and cancel any active timers (intervals/timeouts) from the last run.
code.undo() / code.redo()Step the editor backward or forward through edit history.
terminal.print("msg")Print a literal string into the terminal output.
terminal.clear()Clear all terminal logs.
terminal.close()Hide the terminal panel.
terminal.error()Switch the terminal to the Errors tab.
terminal.help()Print this command reference inside the terminal.
✓ Use code.stop() when a timer runs wild

If a program starts an interval() (setInterval) that keeps firing, the preview never settles. Run code.stop() to cancel every active timer from the last execution before debugging. It's the Neote equivalent of hitting the brakes.

Reading the Main tab

Anything your program sends to showcase(), warn(), or error() appears in the Main tab, color-coded by level. Runtime errors — uncaught exceptions, unhandled promise rejections, window.onerror — show with the line number that matches your source. The bridge that carries these messages is injected automatically by the transpiler, so you never wire it up yourself.

Workflows & Tips

Workflows & Tips

A few habits make Neote dramatically more pleasant to write and debug. These are the patterns that separate a rough sketch from a file you can come back to next week.

1. Lay out the page top-to-bottom, then wire behavior

Write every $ loader for the static page first — header, inputs, buttons, footer — giving each interactive element a /id. Only then start the logic section. The result reads like a contract: the declarative part shows the structure, the logic part shows the behavior, and the /ids are the dotted lines between them.

2. Keep one concern per file

Neote files are cheap and live in neote_tree. Rather than cramming a multi-screen app into one file, split it into focused ones — header.neote, pricing.neote, signup.neote — and link between them with $href. The tree persists across sessions in localStorage, so reorganizing is drag-and-drop.

3. Run early, run often

Ctrl+Enter re-runs the active file instantly. Get into the habit of running after every few lines, especially when a loader or keyword is new to you. The transpiler reports errors with line numbers and a wavy red underline, so the gap between mistake and fix stays tiny.

4. Use the Transpile view to learn

When a result surprises you, click Transpile (or { } Transpiled on this course). Seeing the exact HTML and JavaScript the compiler emitted tells you precisely what a loader expanded to and whether a keyword translation landed where you expected. It's the fastest way to build an accurate mental model.

5. Autocomplete is your memory

Press Ctrl+Space in the editor. The dropdown lists every guide keyword with its translation, every $ loader with its HTML target, and every common slash attribute. You don't have to memorize the tables — just remember Ctrl+Space.

💡 Keyboard shortcuts

Ctrl+Enter run · Ctrl+S save · Ctrl+B toggle explorer · Ctrl+` toggle terminal · Ctrl+Z / Ctrl+Y undo/redo · Ctrl+Space autocomplete.

6. A complete, idiomatic file

This example ties everything together: a styled shell, a form, dynamic list-building, an event handler, and terminal logging. It's the shape a real Neote app takes.

todo-app.neote
// A complete, idiomatic Neote app in one file.
<style>.done span { text-decoration: line-through; opacity: .5; } li { cursor: pointer; padding: 6px 0; list-style: disc; } #newTask { width: 72%; }</style>

$hd("Neote Todo")
$input("Add a task...") /id="newTask" /type="text"
$btn("+ Add") /id="addBtn"
$ul("") /id="list"
$p("0 tasks · 0 done") /id="stats"

st list = doc.element("list")
st input = doc.element("newTask")
st addBtn = doc.element("addBtn")
st stats = doc.element("stats")
st done = 0
st total = 0

func updateStats() {
  stats.innerText = total + " tasks · " + done + " done"
}

func addTask(text) {
  total = total + 1
  st li = doc.create("li")
  st span = doc.create("span")
  span.innerText = text
  li.append(span)
  li.sense("click", func() {
    if (li.classList.toggle("done")) {
      done = done + 1
      showcase("completed: " + text)
    } else {
      done = done - 1
    }
    updateStats()
  })
  list.append(li)
  updateStats()
}

addBtn.sense("click", func() {
  st v = input.value.trim()
  if (v) { addTask(v); input.value = ""; showcase("added: " + v) }
  else { warn("empty task ignored") }
})

input.sense("keydown", func(ev) {
  if (ev.key === "Enter") { addBtn.click() }
})

// seed
for (st i = 0; i < 2; i = i + 1) {
  addTask("Sample task " + (i + 1))
}
showcase("Todo app ready — " + total + " tasks seeded")
